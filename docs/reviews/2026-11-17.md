gateway instances and test credentials.

## Build and runtime checks

- All 131 top-level Go tests passed with the race detector: 77.4% statement
  coverage for the CLI and 87.0% for the gateway. All 33 console tests passed,
  as did formatting, vet, the benchmark smoke, and example-config validation.
- Chrome exercised login, key creation, rotation and deletion, a stale edit
  across two tabs, credential-destination confirmation, Activity, Check, and
  retrying a failed logout. The desktop run used light mode; the 390-pixel
  mobile run used dark mode.
- A real curl client used the intercepting HTTPS proxy with a test CA.
  The allowed request reached the loopback TLS upstream once. A denied
  path, an unknown host, and an unauthenticated CONNECT added no upstream calls.
- With the former container compiler (Go 1.26.6), `govulncheck` reported
  call paths into the standard library for 11 advisories on Linux/amd64.
  Using Go 1.27.4, it reported none for the final Linux/amd64 source, the
  executable extracted from the image, or any of the five packaged binaries.
  The Go vulnerability database snapshot was dated November 11, 2026.
- All five release archives were built from a clean temporary snapshot.
  Their file lists, target architectures, and compiler metadata were checked.
  The packaged macOS/arm64 CLI was run locally. The Linux/amd64 container
  ran read-only as UID 65532, read the public Go vulnerability database
  over verified HTTPS with its built-in CA store, and denied an ungranted path.

## Upgrade notes

Source builds require Go 1.27.4 or newer. A non-root grant ending in a slash,
such as `/items/`, previously matched nothing; it now fails validation.
Remove it if obsolete, or use `/items` if both forms should be accessible.
API scripts can opt into stale-edit protection with `If-Match`; the console
sends it automatically.
